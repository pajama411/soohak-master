01 / 확률의 개념 · 여사건 · 독립시행

10%라면, 열 번 뽑아
한 번은 나와야 하나?

// 실제 게임과 무관한 실험
const success = Math.random() < 0.1;
준비 완료

버튼을 누르면 결과가 표시됩니다.

확통: 여사건과 독립시행

10번 모두 실패할 확률

(1 − 0.1)10 = 0.910
≈ 34.87%
당첨 확률 10%는 10번 중 반드시 1번이라는 뜻이 아님. 각 시행이 독립일 때의 계산!
02 / 컴퓨터공학적 배경 · PRNG

컴퓨터는 랜덤을 계산한다.

선형 합동 생성기(LCG): 이전 상태로 다음 숫자를 계산하는 PRNG의 한 종류

Linear Congruential Generator
Xn+1 = (aXn + c) mod m
a = 21c = 1m = 100seed = 7
SEED = 7
같은 시드 + 같은 알고리즘 → 같은 수열. 그러나 결정적으로 생성된다고 해서 곧바로 ‘확률 조작’은 아니다.
03 / 1단원 경우의 수 + 2단원 수학적 확률

평등하게 뽑았는데…
나머지는 왜 불평등함?

0~8의 균등한 원본 숫자 → % 6
↓　x % 6
P(나머지 = 0) = 2가지 / 9가지
2/9 = 22.22%
P(나머지 = 5) = 1가지 / 9가지
1/9 = 11.11%
모든 원본 숫자의 확률은 같아도, 변환 결과의 경우의 수가 다르면 확률도 달라진다. 이것이 모듈로 편향(Modulo Bias).
04 / 이론적 확률 ↔ 실험적 상대도수

그러면 직접 6,000번 돌려보자.

BUGGY · 단순 % 6
0·1·2 이론값 22.22%3·4·5 이론값 11.11%
FIXED · 기각 샘플링
모든 값의 이론값 16.67%0~5 균등
시뮬레이션 준비됨
그래프 = 실험 결과. 확률 공식 = 이론 결과. “많이 뽑으면 해결된다”는 말은 편향된 코드에는 해당하지 않는다.
05 / 실제 사례와 수학적 모델

그런데 이게 실제 게임에서도?

32비트 정수 → 10억 개의 나머지
232 = 4,294,967,296
4 × 1,000,000,000 + 294,967,296
10억 × 4묶음나머지 2억 9,496만
나머지 값의 범위대응 횟수
0 ~ 294,967,295각 5회
294,967,296 ~ 999,999,999각 4회
확통: 1% 당첨 구간의 실제 확률
가정: 원본 정수 232개가 균등하며 0~9,999,999를 당첨으로 설정
P(A) = (5 × 10,000,000) / 232
의도한 확률
1.000%
계산된 확률
1.164%
상대적으로 약 16.4% 증가. 5 대 4의 비율인 25%와 구분!

※ 2026년 메이플스토리 드롭률 오류를 설명하는 모듈로 편향의 단순화 수학 모델. 실제 게임의 모든 로직을 재현한 것은 아님.

06 / 2단원 조건부확률

그럼 불공평한 숫자를
어떻게 걸러낼까?

Rejection Sampling · 기각 샘플링
let x;
do {
  x = Math.floor(Math.random() * 9);
} while (x >= 6);  // 6,7,8 재추출
return x;          // 0~5
채택 0~5기각 6~8

6·7·8이 나오면? 다시 뽑으면 됨.

확통: 채택되었다는 조건 아래의 확률

A = 나머지가 0인 사건, B = 원본이 0~5인 사건

P(A | B) = P(A∩B) / P(B)
= (1/9) ÷ (6/9) = 1/6
1~5도 마찬가지로 1/6. 조건부확률로 수학적 해결 원리를 확인!
07 / 3단원 확률변수 · 이항분포 · 기댓값

확률 0.164%p 차이.
10,000번이면 얼마나?

INTENDED / 1%
X ~ B(10000, 0.01)
E(X) = np = 10000 × 0.01
100회
모의실험 결과 — 회
BIASED / 약 1.164%
Y ~ B(10000, 0.0116415)
E(Y) = np ≈ 116.4
116.4회
모의실험 결과 — 회
독립인 베르누이 시행을 가정
기댓값은 반드시 그만큼 나온다는 뜻이 아니라 반복 실험의 평균적 수준. 여기서는 독립시행이라는 별도 가정이 필요하다.
